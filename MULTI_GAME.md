# Multi-game build

`build/dinput8.dll` contains the XInput/native-DS4 DirectInput adapter and platform hooks. The DLL selects the config filename from the game executable. It is installed for:

- `Shin Sangokumusou 3\game` — 真三3 / Dynasty Warriors 4: Hyper (DW4 Hyper), reads `SSM3_Tweaks.ini`; four independent D-pad buttons and no left-stick movement bridge. The game keeps its own 1280x960 backbuffer and the borderless window upscales it; all resolution overrides are refused for this build.
- `Shin Sangokumusou 4` — 真三4 Special / Dynasty Warriors 5 Special (DW5 Special), reads `SSM4_Tweaks.ini`; four independent D-pad buttons and a signature-verified native menu map. Same refusal: original render target only, no desktop-sized backbuffer, no perspective rewrite.

`build/dinput8-platform.dll` contains platform hooks and is installed in `Dynasty Warriors 8` (真三国无双7). `Launch.exe` reads `SSM7_Tweaks.ini`; it uses one primary-chain Present so overlay frame counts stay aligned. Larger-than-desktop internal buffers remain intact and the windowed runtime scales them to the desktop. This ports the config-driven width/height rewrite behavior of SM6 DX's `resolution_for_SM6TC.dll`, using 110 separately verified `Launch.exe` sites; the SM6TC offsets are not reused. `internal_render_width` / `internal_render_height` set the engine's render size. Battle camera and HUD viewport width profiles are included. `camera_distance_percent` (50–300; 100=original) moves the 3D viewpoint, reloads from the INI while running, and preserves FOV/HUD scale. Foreground shortcuts default to Ctrl+Alt+PageUp/PageDown (farther/nearer), Ctrl+Alt+Home (100%); keys and step are configurable and adjustments save automatically.

`Shin Sangokumusou 5` (真三国无双5 / Dynasty Warriors 6, `SM5_WIN.exe`) uses `build/dinput8.dll` and `SSM5_Tweaks.ini`. This port is the one build that filters controllers by name: `SM5_WIN.exe` carries a whitelist of DirectInput product names (`Controller (XBOX 360 For Windows)`, `XBOX 360 For Windows (Controller)`, `Logitech ChillStream`, `XUSB Gamepad (Controller)`, several ELECOM/SANWA pads) and silently ignores anything else, so a virtual pad called `MUSOUTweaksPC Gamepad` is enumerated but never selected. `pad_name` therefore defaults to `Controller (XBOX 360 For Windows)` for this executable. The game steers the camera with the right stick, so `pad_axes` defaults to `6` (X/Y/Z/Rx/Ry/Rz: left stick, triggers, right stick) instead of the 2-axis device the rest of the family uses. The D-pad is exposed as a POV hat (`dpad_pov=1`) plus four independent buttons and is never bridged onto the left stick (`dpad_as_left_stick=0`), so it keeps its own bindings and cannot walk the character. Its menus read neither the POV hat nor those buttons, so navigation goes through `dpad_arrow_keys=1`: paired `DIK_UP/DOWN/LEFT/RIGHT` events are appended to the game's own buffered DirectInput keyboard device (`GetDeviceData` capacity 10), the same path SSM6 DX uses. Those menus latch one cursor step per press, so `dpad_menu_repeat_ms` (120 here, 0 elsewhere) releases the forwarded D-pad for `dpad_menu_pulse_ms` every period after a 400 ms delay, which produces the repeated key events and keeps the cursor moving. `native_resolution` and `scale_to_fill` start at `0` — the game renders at the resolution it selected and the borderless window stretches it. This executable imports exactly one user32 function (`MessageBoxA`), so the `CreateWindowExA` IAT slot can never be patched and the usual main-window hook never fired; the borderless resize was dead until the patch learned to poll the process's own top-level windows for the registered class `SangokuMusou5PC` (with a diagnostic that logs every candidate class, plus a fallback that takes the single large visible window when the expected class never shows). A live run now logs `main window watcher started` → `main window hooked class=SangokuMusou5PC bounds=0,0 2560x1440` and the picture fills the screen. `install-ssm5.ps1` makes a timestamped backup.

`Dynasty Warriors 7 DX` (真三国无双6 with 猛将传 DX) uses `build/dinput8.dll` and `SSM6_Tweaks.ini` for `SM6TC.exe`, `SM6EN.exe`, and `SM6JP.exe`. The profile enables XInput/native-DS4 adaptation, independent D-pad buttons/POV, hot-plug, borderless display, and single primary-chain presentation. `native_resolution` and `scale_to_fill` must stay `0` for this build: the engine only draws into the top-left 1920×1080 area of an enlarged backbuffer, and forcing the 3D viewport to the desktop size leaves the 2D layer laid out for 1920×1080, which shows up as a wrong field of view. The game keeps its own render resolution and the borderless window stretches that image. The D-pad never reaches the left stick (`dpad_as_left_stick=0`), so it cannot move the character; menu navigation instead goes through `dpad_arrow_keys`, which appends paired `DIK_UP/DOWN/LEFT/RIGHT` events to the game's own buffered DirectInput keyboard device — user-confirmed working. For `SM6TC.exe` only, the installer also installs the supplied `d3dx9_43.dll` mod loader with `Fix_for_SM6.dll` (facial-expression fix) in `mods`. The bundled `resolution_for_SM6TC.dll` is no longer shipped or installed because it breaks the field of view. XInputPlus proxy DLLs are omitted because the main `dinput8.dll` already owns DirectInput/XInput adaptation. `install-ssm6dx.ps1` makes a timestamped backup; see `THIRD_PARTY_MODS.md` for details.

`OROCHI_Z_TC.exe` (无双蛇魔Z) uses `OrochiZPadX.ini`. Its verified engine size getters and runtime dimensions port the configurable resolution behavior independently of desktop output; the SM6TC offset list is not applied to this different executable. 3840x2160 rendering uses the game primary swapchain for desktop presentation, with a correction for GS sprite Y coordinate overflow above 2048 pixels. Full-screen background depth writes are isolated so preparation maps and result UI retain depth testing. Player battle cameras support the same distance percentage and foreground shortcuts as SSM7; CPU and renderer projections stay synchronized, and preparation maps are excluded. Set both resolution values to 0 for the previous render sizing behavior.

`Sengoku Musou 2` uses `build/dinput8.dll` and `SM2_Tweaks.ini`. It has XInput/native-DS4 adaptation, four independent D-pad buttons and POV (no left-stick movement bridge), close-confirmation removal, and 65 FPS pacing. The available log confirms D-pad states are sent while left-stick axes remain centered; no native menu-map patch is available yet, so menu cursor navigation is not claimed. Its resolution port uses a game-specific in-memory patch that waits for the protected executable to decrypt, replaces its width/height getters, and adjusts HUD/menu geometry; `0/0` follows the active display's physical resolution. The 2.28 DLL and config are installed, but this new resolution path has not yet been confirmed in a live SW2 session; `SM2Resolution.log` will report whether each signature was found.

## D-pad support status

Independent D-pad button output (Buttons 13–16) and POV output are provided by the virtual DirectInput adapter for Orochi Z, 真三3 / DW4 Hyper, 真三4 / DW5 Special, 真三5 / DW6, 真三6 DX, and SW2. The left-stick bridge is disabled for all of these profiles except 真三5, which uses the pulsed mode 2 mirror on top of the POV hat, and 真三6 DX, which uses keyboard-arrow injection instead. Menu navigation and in-game rebinding depend on each game's own input map and are not guaranteed by exposing buttons alone. Orochi Z's menu navigation, independent binding, and lack of battle movement were user-confirmed. 真三6 DX menu navigation and lack of battle movement were user-confirmed through `dpad_arrow_keys` (keyboard-arrow injection into the game's buffered keyboard device). 真三4 / DW5 Special's menu-map patch is present in runtime logs, but in-game confirmation is not recorded. 真三3 / DW4 Hyper's menu-map selector is in code, but its latest available runtime log predates it. SW2's D-pad output is confirmed while its menu map is still unavailable. 真三5 / DW6 has no runtime confirmation yet. 真三7 / Dynasty Warriors 8's platform-only DLL does not provide this controller adapter. Therefore it is not accurate to say every title currently has confirmed D-pad cursor navigation and independent rebinding.

Run `build.cmd` and `build-platform.cmd` from a Visual Studio x86 developer environment to rebuild both variants. `install-targets.ps1` installs only the compatible targets and creates timestamped backups with `manifest.json`; `install-ssm5.ps1` and `install-ssm6dx.ps1` handle the two profiles that need their own supplemental layout.
